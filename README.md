# Startup Compass

An AI startup survival-risk and funding-readiness dashboard for AVENIR Hackathon
4.0 (StartupSpark AI). Python 3.11, Streamlit, Plotly and scikit-learn. Free and
open-source only: no API keys, no LLMs, no paid services. All money values are
**INR lakh**.

> **SYNTHETIC DATA.** Every record and every failure label in this repository is
> generated by `src/data_generation.py`. Model outputs are probabilities for
> decision support, never guarantees. Metrics measured on synthetic labels do
> not establish real-world predictive performance.

## What it does

| Tab | What you get |
|---|---|
| Analyze | Compass dial with the 24-month failure probability and risk band, a 0-100 funding-readiness ring, runway and cash-out month, a sub-score radar, "Why this result" sentences, a 24-month runway forecast and a ranked action plan |
| What-If | Burn, churn, growth and CAC sliders applied to a copy of your inputs; baseline vs scenario dials, the change in points, and each lever's effect on its own |
| Peer Benchmark | Percentile bars against training startups in the same sector and stage, plus a runway vs churn scatter |
| Batch Screening | CSV upload, template download, validation report, Low/Medium/High counts, a ranked and filterable table, results download, and every bad row listed with its reason (bad rows are never dropped) |
| Model & Data | Test-set ROC-AUC, PR-AUC, Brier and recall read from `models/metrics.json`, the 3-model CV table, calibration curve, permutation importance, dataset summary, disclosure and limitations |

## Run it

The committed CSV and trained model mean the app runs on first launch without
retraining.

```bash
python3.11 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Reproduce the data, model and tests:

```bash
python src/data_generation.py        # 6,000 rows, seed 42 -> data/startups_synthetic.csv
python src/train_model.py            # CV comparison, calibration, metrics.json, reports/
pytest -q
```

## Data

`generate(n=6000, seed=42)` builds 7 sectors (SaaS, Fintech, Edtech, Healthtech,
D2C, Agritech, Deeptech) and 3 stages (Pre-seed, Seed, Series A). Net burn =
burn - MRR x gross margin / 100; runway = cash / net burn; LTV = ARPU x margin /
churn. A latent risk combines runway, churn, growth, LTV:CAC, founder experience
and prior rounds plus Normal noise; the 68th percentile is the threshold, so
about 32% of rows fail. 4-8% of founder experience, margin, churn, CAC and LTV
values are blanked, and 25 burn values are multiplied by ten as outliers.

Engineered features (`src/features.py`): net_burn (floored at 0.05),
runway_months (capped at 60), ltv_cac_ratio (0-15), burn_multiple (0-60),
revenue_cover (0-3), burn_per_head, is_profitable.

## Model

80/20 stratified split (seed 42); the test set is used once. Numeric features
are winsorised to the training 1st/99th percentiles, then median-imputed with
missing indicators and scaled; categoricals are one-hot encoded with unknown
categories ignored. 5-fold stratified CV compares Logistic Regression
(balanced, max_iter 2000), Random Forest (300 trees, min_samples_leaf 5) and
HistGradientBoosting. The highest mean CV ROC-AUC wins, and a simpler model
within 0.01 is preferred. The chosen pipeline is calibrated with
`CalibratedClassifierCV(method="isotonic", cv=5)`.

Latest run (synthetic data):

| Model | ROC-AUC | PR-AUC | F1 | Recall | Brier |
|---|---|---|---|---|---|
| Logistic Regression (selected) | 0.891 ± 0.005 | 0.782 ± 0.008 | 0.716 ± 0.014 | 0.829 ± 0.010 | 0.138 ± 0.006 |
| Random Forest | 0.879 ± 0.004 | 0.758 ± 0.020 | 0.709 ± 0.008 | 0.781 ± 0.009 | 0.142 ± 0.003 |
| HistGradientBoosting | 0.874 ± 0.005 | 0.745 ± 0.011 | 0.679 ± 0.013 | 0.661 ± 0.015 | 0.138 ± 0.004 |

Held-out test, calibrated: ROC-AUC 0.900, PR-AUC 0.807, F1 0.720, precision
0.742, recall 0.698, Brier 0.119, accuracy 0.826.

## Scoring

Risk band: Low < 0.25, Medium 0.25-0.50, High > 0.50.

| Sub-score | Formula (0-100) |
|---|---|
| Runway | min(runway / 18, 1) x 100 |
| Unit economics | min(LTV:CAC / 3, 1) x 100 |
| Growth | clip((MoM growth + 5) / 15, 0, 1) x 100 |
| Retention | max(0, 100 - 8 x monthly churn) |
| Traction | mean(min(revenue_cover / 0.6, 1), min(months / 24, 1)) x 100 |

A sub-score whose input is missing is 50.

Readiness = clip(0.25 Runway + 0.25 Unit economics + 0.20 Growth + 0.15
Retention + 0.15 Traction - 15 x probability, 0, 100).

## Explanations, What-If and actions

- **Why this result:** for each factor group (Runway and burn; Revenue and
  growth; Unit economics; Retention; Team and experience; Funding history), its
  fields are replaced by the training median or mode and the model is re-run.
  Delta = baseline - replaced, in percentage points; positive means that group
  is raising risk. The top 3 each way are shown as sentences.
- **What-If:** `apply_levers` scales burn and CAC, shifts growth, and scales
  churn while rescaling LTV by old/new churn so the unit economics stay
  consistent.
- **Action plan:** cut burn 15%, cut churn 30%, add 3 points of growth, cut CAC
  20%, raise prices 10%, add 6 months of burn to cash. Each one is re-run through the model and
  sorted by risk change. These are model estimates, not guaranteed outcomes.
- **Runway forecast:** cash_t = cash - net_burn x t at a constant (conservative)
  net burn, for the current plan and the best action. The cash-out month is the
  first t with cash <= 0 (none if profitable).
- **Peers:** training rows in the same sector and stage, falling back to the
  same stage when there are fewer than 30. For churn and burn multiple, lower
  is better.

## Limitations

- All records and labels are SYNTHETIC. The scores do not estimate real startup
  failure rates.
- Isotonic calibration is a step function, so it goes flat at the extremes. A
  startup scored near 0% or 100% may show no change from small edits; the app
  warns when this happens.
- Inputs well outside the training range (for example, very large burn or MRR)
  are clipped to the training 1st/99th percentiles. The app flags them as less
  reliable.
- Group-replacement explanations reflect associations the model learned, not
  causes.
- Important real-world factors such as market timing, founder dynamics and
  macro conditions are not modelled. Inputs are self-reported.

## Deploy (Streamlit Community Cloud)

1. Push this repository to GitHub, including `data/startups_synthetic.csv` and
   `models/model.joblib`.
2. On share.streamlit.io choose **New app**, pick the repository and branch,
   and set the main file to `app.py`.
3. Under **Advanced settings** choose Python **3.11**, then deploy.
   `requirements.txt` pins every dependency.

If deployment fails, run it locally with `streamlit run app.py` and record a
screen video of the demo click-path for the submission.
